# CiteGraph 스코어링 v3.0 — 사업성 재설계 노트

> 첨부 워크북(`CiteGraph_Scoring_v3.0_사업성재설계.xlsx`)의 설계 배경과 v2.3 대비 변경 논리를 정리한 문서입니다. 체크리스트 표 자체는 워크북의 `1_사업성검증체크리스트` 시트를 참고하세요.

## 왜 다시 설계했나

v2.3 문서는 "점수 → 액션플랜"을 판매하는 SaaS의 근거 자료로 쓰기엔 세 가지 근본 결함이 있었습니다. 가중치 근거가 논문 방향성만 빌려오고 실측 검증이 없었고, 렌더링·WAF 차단 신호가 가중 점수와 게이트에 이중으로 반영됐고, 각주 번호가 참고문헌 목록과 맞지 않아 감사에 취약했습니다. v3.0은 이 세 가지를 구조적으로 막도록 다시 짰습니다.

## 구조 변경 핵심

**Tier 0 — 차단 플래그를 점수에서 완전히 분리했습니다.** JS 렌더링 의존성과 WAF 차단은 더 이상 가중 점수 항목이 아니라 별도의 바이너리 배지입니다. 이렇게 하면 같은 신호가 R_TECH 합산에도 들어가고 게이트로도 곱해지는 이중 계산이 원천적으로 불가능해집니다. 또한 단발성 오류로 점수가 널뛰지 않도록, 3회 연속 관측이 확인되어야 차단이 확정되도록 했습니다(하루짜리 403 로그 하나로 전체 점수가 0이 되던 v2.3의 문제 해결).

**Grade 체계로 재현성을 등급화했습니다.** Grade A는 결정론적 검증기 기반이라 몇 번을 재계산해도 값이 동일합니다. Grade B는 외부 데이터(예: sameAs 링크)를 조회하는 방식이라 데이터 신선도에만 의존합니다. Grade C는 LLM 판정이라 확률적입니다. S_SEO는 Grade A만으로 구성해 "SLA로 보증 가능한 점수"로 분리했고, R_SEM의 Grade C 항목은 3회 샘플링 후 중앙값과 표준편차를 함께 저장하도록 해서, 화면에는 "68~74점" 같은 구간으로 노출하고 단일 소수점으로 과신하지 않게 했습니다.

**Weight Status로 가중치의 신뢰 수준을 명시했습니다.** VALIDATED는 자체 데이터로 통계적 상관관계가 확인된 가중치, CALIBRATING은 데이터를 모으는 중(n<30), HYPOTHESIS는 외부 연구의 방향성만 빌려온 상태입니다. 예를 들어 `SR-GF-LLMSTXT`(llms.txt 제공 여부)는 업계에서 논의되는 신호지만 아직 채택률이 낮아 HYPOTHESIS로 표시하고 가중치도 보수적으로 15점만 배정했습니다. 이렇게 상태를 명시하면, 나중에 실제 인용 데이터를 모아 VALIDATED로 승격시키는 경로가 제품 로드맵 자체가 됩니다.

**각 체크마다 조치·난이도·출처를 강제로 붙였습니다.** v2.3은 체크리스트였지만 v3.0은 액션 카탈로그입니다. 모든 항목에 "무엇을 어떻게 고치는지"와 "난이도(S/M/L)"가 있어야, `7_액션플랜매트릭스` 시트처럼 손실점수를 난이도로 나눈 우선순위 점수가 자동으로 계산되고 이것이 곧 상품의 산출물이 됩니다.

**세그먼트 가중치 배율을 분리했습니다.** 블로그, 이커머스 PDP, 문서/KB, 로컬 서비스업은 같은 체크라도 중요도가 다릅니다(예: PDP는 저자 신뢰도보다 상품 스키마가 중요, 로컬 서비스는 E-E-A-T 민감도가 높음). 기본 배점에 세그먼트 배율을 곱해 최종 점수를 산출하도록 분리했습니다.

## OCI 공식 v3.0

```
차단 플래그(BLK-RENDER / BLK-WAF / BLK-NOINDEX) 활성 시:
    OCI = 0  (배너로 사유 표시, 점수 계산 자체를 하지 않음)

미활성 시:
    OCI = (0.40 × R_TECH + 0.60 × R_SEM) × α_SERP

    α_SERP는 C-SEO Bench(Puerto & Gubri et al., 2025, arXiv:2506.11097)의
    "조직 검색 순위가 지배적 요인"이라는 결론 방향은 실제 논문과 대조 확인됨.
    다만 원문서의 "7.6배" 같은 구체적 배수는 해당 논문 초록에서 확인되지 않아 삭제했고,
    단계별 배수(1.00 / 0.85 / 0.65 / 0.40 / 0.05)는 HYPOTHESIS 상태로 유지.
    자체 데이터로 백테스트 후 VALIDATED로 승격 필요.
```

## 다음 단계 (제품화 로드맵)

1. Grade A 항목(S_SEO, R_TECH 일부)부터 프로덕션에 태워 "보증 가능한 점수"로 먼저 출시
2. Grade C 항목은 베타 라벨로 별도 노출, 신뢰구간 UI 우선 구현
3. 초기 고객 20~30개 사이트를 대상으로 점수 변화 전후 실제 AI 검색 인용 빈도 3~6개월 추적
4. 추적 데이터로 HYPOTHESIS/CALIBRATING 가중치를 회귀분석 기반으로 재조정, v4.0에서 VALIDATED 비율 확대
5. `7_액션플랜매트릭스`의 우선순위 로직을 실제 대시보드 기능으로 이식 (손실점수 ÷ 난이도)
